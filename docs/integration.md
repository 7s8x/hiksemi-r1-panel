# 全面整合实施说明

本分支基于 v1.5.2 后的 main，仅准备源码和测试，不部署、不发版、不改历史标签。

## 第一批：模块与协议

- `r1_host_sampling.py` 管理只读主机查询；共享采集器不再导入面板或 Web 渲染模块。
- `r1_storage_queries.py` 提供 `nvme_capacity()`、`bay_capacities(disks)`；旧模块仅作兼容导出，无独立缓存。SSH 限制、容量协议、换盘失效和分组间隔保持。
- `r1_snapshot.py` 集中内部默认值和 fast 字段；公共输出继续独立白名单脱敏。后台公共帧使用空帧工厂，失败不会返回面板默认结构。
- identity 不再有第二层 TTL；唯一调度在 collector。
- `r1_rgb_io.py` 承担 SMBus 原语；正式 RGB 控制不再导入试验/探测脚本。旧 CLI、文件及发行入口保留。

后续批次分别优化单轮采样、实体屏刷新、按需 PNG。独立温控策略与运行服务不因本分支而改变。

## 第二批：单轮采样

每个fast周期新建一次hwmon索引，传感器文件单轮读取（含失败）只一次；不跨轮缓存拓扑。CPU展示仍读temp1，风扇依据取全部核心/封装温度最大值并保留范围/盘位/重复传感器检查。设备读取失败只清空对应字段，未知整轮异常仍由collector兜底。独立温控源码不变。

## 第三批：实体屏刷新

每次仍读取共享快照及当前控制状态，生成最终SVG；只有页面、SVG内容和分组有效状态相同才跳过Cairo栅格化和写屏。时钟、主题、倒计时和RGB可见状态自然进入SVG比较。切页/唤醒强制绘制，背光/VT/写屏顺序保持，mmap保留。metrics新增prepare耗时与render_cache_hits计数，缓存命中不冒充render/fb_write。写屏或绘制失败不更新缓存。
