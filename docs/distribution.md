# 分发、配置与验收

适用范围为 HS-AFS-R1 + PVE，固定 376×960 前屏。版本对应的 Linux 安装、实体现场及持续观察结果见 Release。无实体屏的安装验证仅覆盖软件安装和服务边界，不代表通过显示硬件验收。

## 配置约定

- `/var/lib/r1-panel/site.json`：非秘密配置，示例见 `site.example.json`。默认沿用 R1 的四个 SATA 端口、PVE 节点 pve、VM 100/111、local/local-lvm。显式指定的配置不存在或无效时拒绝启动；不会悄悄退回默认机器配置。
- `occupied_bays` 表示期望插盘的物理盘位，而非传感器数量。缺少期望盘、出现未登记盘、重复映射或传感器无法唯一归属，温控均请求两路全速。0 个 SATA 时机箱仍保持最低 PWM 120 和 CPU 高温辅助。
- 同一型号 R1 的 SATA 控制器 PCI 路径也需要安装者核对。`/dev/sdX` 不能作为固定盘位依据；显示顺序固定 NVMe、BAY 1–4。
- 存储源必须由安装者确认确实归属所显示的 NVMe。容量来自 PVE 及可选 DSM 只读源，不把 raw 盘大小当成客户机可用空间；多盘卷仍不推断单盘用量。
- 本机 SSH 查询配置仍独立存放于 `storage-usage.json`，不要将其、授权密钥或主机指纹作为发行资产。只读通道要求固定主机指纹、强制命令与最小授权。
- `driver.env` 由温控 systemd 单元读取，设置 `R1_IT87_MODULE` 和 `R1_IT87_SHA256`；内核升级后重新构建验证，不自动降级检查或使用 force_id。

## 数据有效性

前屏与 Web 只读取 `r1-collector.service` 原子发布的 `/run/r1-collector/snapshot.json`（目录 0700、文件 0600），不在采集失败时重复查询主机。快速传感器/负载/内存每 5 秒、VM 批量查询每 60 秒、NVMe/PVE 容量和设备信息每 300 秒、可选群晖 SSH 容量每 1800 秒。启动错开慢任务；单独慢线程串行查询，超时不阻塞快速采样，不积压补跑。换盘先清除旧容量，再合并触发一次提前查询；旧盘在途结果不复用。

各组独立记录采集时间，超过两倍周期失效。查询失败清空本组，VM 错误、缺失或重复 ID 显示 UNKNOWN；不会因其他字段刷新而续期旧容量。停用采集器会使展示值失效，但不会停止独立温控。温控仍按自身 5 秒自动／1 秒全速节奏直接读取传感器，不使用展示缓存。

可在采集服务的 systemd drop-in 覆盖 ExecStart，使用 `--fast-interval`、`--vm-interval`、`--nvme-interval`、`--dsm-interval` 设置秒数。默认前屏绘制和 Web 只读图仍每 15 秒更新；全速倒计时保留 1 秒刷新。RGB 状态读取缓存 15 秒，操作后立即读回。无原始快照的公开 HTTP 接口，免登录输出仍屏蔽序列号及虚拟机名称。

后台快照在采集失败后失效，超过两个采样周期仍未更新也失效；不再沿用旧温度、风扇或 VM 数据。快照附 `freshness` 元数据。此时 Web 图返回不可用或实体字段显示缺失，不假装刚刷新了旧读数。

`--metrics` 默认为关闭，开启后每分钟报告采集、绘制、写屏耗时及 Python 自身 CPU、RSS、服务重启数。`metrics_schema=1` 不是发行版本号。分钟 P95 不能平均为全程 P95。日志另含固定边界的延迟直方图，可合并计算 P95 所在区间（不是精确数值）；含子进程的服务 cgroup 累计 CPU 纳秒与 Python 自身 CPU 分列。cgroup v2 路径或正式服务名无法确认时该项为 null；应另行采集服务总资源。字段不可用按固定类别计数，不记录实际值、VM 名称或硬盘身份。外部子命令的单独 CPU 拆分仍需专门观测，不能以 Python CPU 代替完整采集链成本。

## 依赖及安装验证

共享采集版的前屏 `--metrics` 中 `collect` 表示读取共享快照的耗时，不再包含外部查询，不能与旧版采集耗时直接比较。真实查询耗时见采集服务的 `collect_job` 日志；性能对比须合计前屏、Web 与新增采集器的 cgroup CPU（包含子进程），温控另列。

Python 3.12/3.13 标准库；Linux Cairo、Fontconfig 和仓库内完整 Noto Sans SC 字体；PVE 提供 pvesh/pvesm/qm；触屏需 chvt、正确 fbdev/触控节点；驱动需与运行内核匹配；TLS 初始化才需要 openssl。依赖的安装由维护者单独执行，不自动安装或从网络运行脚本。

先运行只读 `r1_doctor.py`，再用 `.venv/bin/python run_offline_tests.py` 离线测试。该入口阻止测试意外写入临时夹具以外的路径及调用未预期的外部控制命令；它是测试回归防护，不是运行未知代码的操作系统沙箱。doctor 不触发模块加载或写入 PWM/RGB，但也不能证明屏幕能刷新。真实模块构建、帧缓冲布局、服务权限和 TLS 链路需要在目标 Linux 上验证。

在干净目标环境准备 venv、依赖、显式配置和驱动后，按 README 顺序启用服务。不要直接把他人的 `/var/lib` 或运行目录覆盖过去；升级保留本机配置，按版本白名单更新程序。升级前备份代码和服务，设置独立回退，再只重启必要服务。

## 发布门槛

1. Python 3.12/3.13 离线与真实 Linux 安装验证，HTTP/TLS、反代、认证和只读页分别验收。
2. 独立回退保护下现场验证两主题、四页正反切换、黑屏回控制台、温度及控制状态刷新。性能试验不操作实际控制按钮。
3. 采集、温控或显示链路候选完整运行 24 小时；观察期间相关运行代码改变须重新计时。安装初始化及文档改动单独记录并验证，不沿用未实际执行的长测结论。记录服务整体 CPU/RSS、异常/重启、字段不可用、显示告警、业务负载和页面停留。结束后再现场复核。
4. 审核全部分支、标签及 Git 历史，不只扫描当前源码。真实凭据先撤销轮换；历史改写与仓库公开另行确认。
5. 审核第三方字体、驱动来源与品牌资产的分发依据。自有代码保留 MIT License 及 Copyright (c) 2026 7s8x；字体保留其独立 SIL OFL 1.1。版本说明放入对应 Release，主 README 保留面向使用者的说明。
6. 用白名单生成发行文件及 SHA-256 清单；主机配置、驱动二进制、FPK、备份、测试日志与性能数据不进入发行包。旧版校验清单留在其历史版本中，不冒充当前清单。
